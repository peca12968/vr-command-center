# VR 場地配置檢查

## MR 場地水平校正試算

控制台 0.31.11 在「任務庫與編輯」提供三點校正試算。全館主控先選房間，再輸入同三個地面標記的遊戲房間本地 X、Z 和同一追蹤座標系的 X、Z，單位為公尺。預填的房間標記可依場地位置調整。輸入完成後按「核對校正」。

A 定位原點偏移，A 到 B 定出方向。A、B 在兩套座標中都須相距至少 0.5 公尺，遊戲標記 C 須離開 A、B 連線至少 0.5 公尺。只用 A、B 求旋轉與位移，C 用來獨立核對方向及誤差。比例固定為一比一。三個標記的平面誤差都在 5 公分內，才可下載房間專用 JSON。5 公分是目前軟體試算門檻，場館安全及跨裝置定位須實測。

`POST /api/room-alignment` 接受 `roomId` 及三個依 A、B、C 排列的 `markers`，每組含 `room`、`tracking`，各有 `x` 和 `z`。房間座標在 ±6 公尺內，追蹤座標在 ±100 公尺內。回應 `room-floor-alignment-v1` 包含原量測值、各標記的對齊座標與誤差、`yawDegrees`、房間本地 `translation` 和全館 `roomOrigin`。JSON 以遊戲 Y 軸旋轉方向計算，正 90° 會把追蹤 +Z 轉到房間 +X。換算全館座標時，先將追蹤點旋轉並加上本地位移，再加全館房間原點。

試算與下載獨立於任務版本及開場。 [驗證紀錄](PROGRESS.md#2026-11-08-mr-場地水平校正試算)

### Quest 3 場地對位

Unity 0.42.0 可讀取對應入場房間的校正檔。用 `deploy-quest.ps1 -AlignmentFile` 隨玩家設定部署。匯出的檔案提供房間 A、B、C 的位置。每台頭盔在進入 Preparing 或 Paused 後，依畫面提示把左控制器的追蹤點放到 A、B、C 正上方，逐點按左扳機。使用同一控制器握法與朝向，並維持頭部及雙手追蹤。程式使用 OpenXR 的地板原點及控制器 X、Z，三點都通過原 5 公分門檻後才將頭部、雙手和瞄準方向轉換到全館座標。

首次量完請回到頭盔顯示的房間本地 X、Z。伺服器沿用原有規則，第一筆姿態須在指定出生位 0.5 公尺內。已送過有效姿態時，提示會顯示最後一筆有效姿態的 X、Z。追蹤原點更新或應用程式暫停後，需在 Preparing 或 Paused 重新量測。錯房、三點不符或地板追蹤不可用時，頭盔會暫停送出姿態與武器輸入。 [Unity 追蹤原點事件](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/XR.XRInputSubsystem-trackingOriginUpdated.html)

目前驗證使用 Unity Editor 模擬的追蹤座標。Quest 3 實機量測、房間地板高度、MR 透視和跨頭盔共用定位仍待驗。 [Quest 3 部署](QUEST3.md#quest-3-場地對位部署)

Quest 3 開發版可選用透視查看實體標記，再依相同的 A、B、C 流程對位。 [透視部署](QUEST3.md#quest-3-透視呈現)

## 全館敵軍策略

Windows 管理包 0.31.36 起，主控可在「全館敵軍策略」選擇守備、巡邏或推進，並開啟或關閉自動攻擊。確認視窗列出房號、場次數及設定。只涵蓋執行中的場次，獨立場在同一筆管理交易保存各場命令，五房合併則只保存一筆。

各場保留原有的敵軍目標數，房控可用個別場次的敵軍設定調整增援。若任一目標的場次階段或敵軍設定已變更，管理端會拒絕整批。遺失回覆可重送原請求。房卡收到對應原命令序號與策略的有效快照後才顯示「已套用」。快照過期會回到待確認，個別場次改寫會清除本場的全館標記。

管理包 0.31.58 的房卡也會確認個別場次的敵軍設定。房卡分列全場目標、本房快照中的在場數及存活數。遊戲端尚未確認或快照已過期時，只顯示管理端目標。按「檢視敵軍快照」可在原房俯視圖停在確認該策略的一格。觀戰與回放會顯示各格實際保存的行為及自動攻擊開關。

### 核對最近一批敵軍策略

管理包 0.31.69 在「全館敵軍策略」下方顯示最近一筆全館命令。各房列出原命令序號、當時的全場目標及目前確認狀態。合併場的五房共用一筆命令序號，個別房仍顯示各自的在場與存活數。重新登入後，主控可從原命令紀錄讀回這一批。

- **遊戲端待確認**表示管理端已受理，仍在等候相同場次及命令序號的有效快照。快照過期也會回到此狀態。
- **遊戲端已套用**時可按「檢視敵軍快照」，在該房俯視圖停在符合原策略的保存格。
- **已被較新的敵軍設定覆寫**或**原場次已結束**會保留原房號、命令與目標數。控制台 0.31.198 可按「查找原敵軍畫格」，在原房間俯視圖停在該指令的第一個有效執行畫格，查看當時的行為、自動攻擊、在場及存活數。房號重新分配後仍會開啟原錄製。該命令序號缺少有效畫格時，會顯示查找結果。

管理包 0.31.251 會在原策略於該房生效期間查找畫格。暫停、恢復等命令可以推進序號。其他房間的覆寫不會截斷本房查找，本房改成自訂策略、選擇沿用全館，或全場再次下達策略時則會建立新界線。主控可在原敵軍畫格端點加上 `roomId`，取得所選房間的 `enemyPopulations`、實際畫格 `observedSequence` 與已知的 `supersededAtSequence`。省略房號時會找第一個全場都沿用原策略的有效畫格。`latestEnemies` 可提供 `supersededRoomIds` 標示個別房間的覆寫。

完整場次回放可從全館收尾開啟。

主控的 `GET /api/venue/phase` 有紀錄時會提供 `latestEnemies`，包含原 `requestId`、記錄時間、策略與各場的 `sessionId`、`appliedAtSequence`、`targetCount` 和 `state`。`Current` 代表管理端仍使用該命令。控制台會再以同房即時快照核對遊戲端套用。

`GET /api/venue/phase` 的 `enemies` 預覽提供各場的 `sessionId`、`phaseSinceSequence`、`enemiesSinceSequence` 與房號。`POST /api/venue/phase` 用 `SetEnemies`、原目標序號與 `enemyPolicy` 的 `behavior`、`autoAttack` 送出，使用同一 `Idempotency-Key` 可取回原回條。`GET /api/rooms/readiness` 的 `venueEnemies` 會回傳策略與有效快照序號。

同一回應的 `enemies` 同時涵蓋全館和個別指令，包含 `setting`、`venue`、`targetCount`，以及確認後的原 `streamId` 和本房 `population`。房卡開啟回放時會核對原指令序號、策略和本房人數。場中加兵仍依原增援條件處理。

保存全館敵軍策略紀錄的管理資料庫須由 0.31.36 或更新的管理包開啟。

## 場中敵軍增援

控制台 0.31.13 的敵軍目標數量是整場總數。管理服務依已保存任務的出生候選點檢查每次加兵。五房連線按房號分配，餘數由較小房號先分配。超過上限會在寫入前回傳 HTTP 400 和本場上限，保留原設定與待修改的表單。可用同一個命令識別提交修正後的內容。

遊戲伺服器 0.45.0 先使用符合通行空間與 0.7 公尺敵軍間距的候選點。暫時占用的名額每 20 個活動 tick 再檢查，其他房間可先增援。策略、天氣和場次生命週期照常套用。已存在的敵軍保留識別與狀態，降低目標會從分配順序的末端撤除。觀戰及回放顯示該幀實際敵軍與存活數。

新版伺服器與管理服務須配套使用。錄製標頭的 `reinforcementVersion: 1` 允許進行中記錄各房目標之內的實際人數，準備幀仍要求完整初始名額。舊錄製延用總數精確核對。戰後可從暫停回放的設定清單查看逐房增援與撤除的畫格。 [回放操作](WORLD_RECORDING.md#查閱錄製中的設定切換) [本機驗證](PROGRESS.md#2026-11-09-場中敵軍增援)

## 合併場分房敵軍策略

管理台 0.31.119 在套用本房策略時核對載入的版本。同一房已被另一位操作員修改，或主控已重設全場策略時，原草稿會保留。按「載入目前策略」會讀取新值並取代草稿。其他房的修改可獨立送出。若本次套用的回覆未確認，可用「重試確認結果」核對原命令。

使用管理控制台 0.31.98 與遊戲伺服器 0.50.0。合併場的遊戲來源附掛後，場次下方會顯示「合併場分房敵軍策略」。房控可選本房，主控可選合併場的任一房。取消「沿用全場策略」後，選擇守備、巡邏或推進，再選擇是否開啟自動攻擊。敵軍依各自房間的策略行動，敵軍總數仍由全場設定管理。

勾選「沿用全場策略」並套用會清除該房覆寫。主控送出全場或全館敵軍設定時，會讓合併場各房回到新設定。房卡以實際保存快照確認本房策略。觀戰選擇單房時顯示該房策略，暫停回放後也可用該房的設定清單查找變更。

控制台 0.31.99 會在房卡保留「本房恢復沿用全場策略」的確認狀態。遊戲端確認後，可按「檢視敵軍快照」停在原房、原錄製及已觀察該指令的一格。全館預覽會列出套用時將清除分房策略的房間。預覽後若有房間更新策略或恢復沿用，送出時會要求重新查閱。

合併場以原 `POST /api/sessions/{id}/commands` 接受 `SetRoomEnemies` 及 `roomEnemyPolicy`。其中 `roomId` 為目標房間，`policy` 包含 `behavior` 和 `autoAttack`，設為 `null` 則沿用全場。遊戲來源在附掛戰鬥串流時宣告 `roomEnemyPolicyVersion: 1`。房控憑證限本房，原場次與其他房的權限沿用。回放核對原畫格所觀察的管理序號和逐房策略。

全館 `SetEnemies` 請將預覽提供的 `roomEnemiesSinceSequence` 與原目標序號一起送出。既有封存的原請求仍可用原內容取回回條。逐房命令的房卡 `enemies.inherited` 表示該房是否已恢復沿用全場。

## 複製物件成列

控制台 **0.31.70** 可在「任務庫與編輯」選取現有物件，展開「複製成列」，輸入份數和每份的 X／Z 位移，再選「預覽」。正 X 向右，正 Z 向上，負值可往反方向延伸。每份沿用原物件的素材、Y 與旋轉角度，依序套用一倍、兩倍等位移。座標和角度欄可直接輸入並保存小數，拖曳和方向鍵仍以原步長操作。

半透明預覽暫時顯示在配置圖上。每批最多 20 份、整個配置最多 500 個物件，兩軸位移至少一項非零，各複本中心須在配置圖的 ±10 公尺內。套用後整批加入草稿，可用一次復原或重做。修改參數或物件、收合工具、離開頁籤及開始儲存會清除預覽。

套用後會執行既有草稿場地檢查，顯示重疊、超出實際場地或阻擋出生位等問題。操作員保存下一版後，可從任務版本匯出或選用該配置開場。

## 批次移動場地物件

在「任務庫與編輯」展開「批次移動與旋轉」，勾選物件或全選，輸入房間本地 X／Z 位移後按「預覽調整」。配置圖以原物件編號標示半透明目的位置。正 X 向右，正 Z 向上，負值可朝反方向移動。

旋轉欄為 0 時，「套用調整」會一次平移所選物件，保留各件的高度、方向、素材及清單順序。改變選取、位移或角度會清除舊預覽。任何一件物件的中心超出編輯圖 ±10 公尺時，整組不會套用。

整組位移可用一次復原或重做。套用後，既有場地檢查會核對實際房間邊界、物件重疊與出生位。保存版本後，可在開場預覽核對新配置，或匯出範本供另一個管理實例使用。

### 批次旋轉場地物件

控制台 **0.31.131** 可輸入 -360° 至 360° 的旋轉量，包含小數。以所選物件中心的平均位置為轉軸，正角度從配置圖看是順時針。預覽的十字標示原轉軸。每件物件的位置及方向一起旋轉，再加上 X／Z 位移。只選一件時可在原地轉向，或接著平移。完整一圈等同 0°。

確認預覽後一次套用，整組位置和角度可一起復原或重做。保存的新版本與下載的範本會保留本次配置，原版本可供日後載入。

### 套用前檢查物件預覽

控制台 0.31.150 的「複製成列」與「批次移動與旋轉」會先用現有場地規則檢查預覽後的完整配置。清單指出包圍盒越界、重疊、出生位受阻等問題。若問題涉及預覽物件，圖上會以紅色虛線標出，編號對應套用後的配置。基本檢查通過但找不到通往中線的取樣路徑時，預覽會列出受影響的席位。

檢查時保留原草稿、原配置圖的通路及復原紀錄。調整參數、物件選取、任務模式或敵軍數量會清除舊預覽，延遲回來的結果也會丟棄。檢查完成或暫時無法取得結果時，仍可把預覽套用為草稿繼續修改。保存版本後，建立場次時仍會依原流程檢查。

## 出生位通路預覽

控制台 0.31.7 可預覽五個出生位到場地中線的路徑。草稿通過基本配置檢查後，虛線會畫出找到的路徑，橘色出生位表示未找到取樣路徑。開場區顯示所選已儲存版本的摘要。操作員可保留刻意設計的封閉防線。

控制台 0.31.19 在有效配置仍有出生位無取樣路徑時，提供「試算移除選取物件」。在配置圖或選單選一件掩體後按下，即可查看移除後新開通的出生位。試算中淡化該物件，並用黃色虛線疊加新增路徑。草稿原通路及出生位標記保留，可按「清除試算」回到原畫面。要採用結果，在物件欄修改或移除後再儲存任務版本。

試算使用原 `POST /api/mission-layout` 計算暫時排除單一物件的配置。切換物件、修改配置、載入草稿、離開編輯頁籤或登出會丟棄該次試算。一次只比較一件物件的影響。

預覽從房間本地座標的 `Z = 0` 中線開始搜尋，使用 0.5 公尺格點和四方向相鄰格。控制台 0.31.76 在任一出生位找不到路徑時，再以 0.125 公尺格點搜尋該席，保留原已找到的路徑。草稿及保存版本的平面圖會列出採用細格取樣的席位。每段沿用遊戲既有的 0.3 公尺通行半徑與 `ArenaWalkSurface.ClearSegment`。結果仍受格點取樣限制，運行中的敵軍路線及實體 MR 場地另行驗證。

VR 與 MR 的草稿及已儲存配置可回傳 `routePreview`。其中有 `step`、`targetZ` 及五席的 `path`，路徑點包含 `x` 和 `z`。採用細格的席位另帶 `sampleStep: 0.125`。空路徑表示兩次取樣都未找到路徑。未通過基本檢查時停用預覽。 [測試與版本](PROGRESS.md)

Windows 三包測試可加 `--check-layout-preview`，使用有缺口的已儲存配置，核對預覽和封存世界中的沙包位置。再加 `--check-layout-fine-opening` 可用偏移的窄缺口，核對細格路徑及原沙包與油桶座標。 [三包測試方式](WINDOWS_SERVER_PACKAGE.md#三個可攜包整合驗證)

### 開場前查看保存版本平面圖

控制台 0.31.122 統一草稿、保存版本與複製預覽的旋轉方向。以正 Z 朝上的平面圖來看，正 45° 的沙包長邊由左上延伸至右下，與遊戲座標一致。

草稿與開場平面圖各有「顯示玩家通行邊界」，配置通過檢查後可開啟，預設關閉。青色虛線框標示玩家中心受牆壁限制的邊界，距牆 0.3 公尺。琥珀色線框將物件方盒沿局部 X／Z 各向外擴 0.3 公尺，表示玩家中心受掩體阻擋的範圍。物件外框與出生位通路會一併保留。勾選屬於檢視設定，可用來比對虛擬配置，實體 MR 場地須另行量測。

控制台 0.31.45 在「準備新場次」完成場地檢查後，可展開「查看保存版本的場地平面圖」。圖中顯示所選保存版本的掩體位置、旋轉、遊戲碰撞包圍盒、五個出生位和到中線的取樣通路。右方是房間本地 +X，上方是 +Z。五房各自獨立或全連線時，各房以相同配置套用至自己的房間原點。

有配置問題時，紅色標示圖框內涉及的物件與檢查列出的受阻出生位。超出圖框的物件可從問題清單查找。橘色出生位表示有效配置中沒有找到取樣通路。切換版本或連線模式後，畫面隨對應檢查更新。編輯頁中的未儲存位置、角度及通路試算各自保留，開場圖只讀取選定的保存版本。 [驗證紀錄](PROGRESS.md#2026-11-09-保存版本的開場平面圖)

### 複驗保存版本的鍵盤通路

對照工具使用原 Windows 開發版及隔離管理實例。依 `stage.json` 所列的 PID 確認本輪玩家視窗。在 `prepare-wall` 和 `prepare-opening` 階段，若遊戲顯示 Unity 開發訊息，先在「等待開始」期間收合，再提供該階段的確認檔。開場後只依階段指定次數按 W。確認檔名稱由 `review` 指定，包含 `version: 1`、`stage` 及 `pid`。有 W 輸入的階段另外寫入實際完成的 `key: "w"` 及 `taps`。正式結論以伺服器接受的座標、封存回放和戰績為準。 [Windows 驗收紀錄](PROGRESS.md#2026-11-10-保存版本的-windows-鍵盤通路驗收)

此配置契約由v0.18導入，v0.19新增步槍素材後維持version1／vr-room-v1。最新API／UI須一起部署，配置檢查不依裝飾武器模型改變。

檢查契約為 version 1、rules `0.8.0`，用於每房 12 × 12 公尺的虛擬場地。VR 使用 `vr-room-v1`。控制台 0.31.12 的 MR 任務使用 `mr-room-v1`，沿用相同的物件、出生位與初始敵軍容量檢查。實體場地的對位另由各頭盔完成。

在「任務庫與編輯」加入／移動／旋轉物件後，控制台自動檢查草稿，紅色標示涉及的物件。點擊問題可選取物件並修改數值；五個圓形為真正出生位的 0.3 公尺通行預留。預覽可切換單房／全館，以核對初始敵軍需求。畫布顯示 ±10 公尺供編輯，框內 ±6 才是目前 VR 場地。

草稿有問題仍能另存或保存下一版。開場選用的是不可變的已保存版本。選取版本及連線模式後，開場區重新讀取該版本的報告。檢查未完成或不支援版本時，建立按鈕會停用。後端也獨立拒絕虛擬配置無效的 VR 與 MR 場次。問題修正後保存下一版，再明確選用該版。

| 規則 | 實際判定 |
|---|---|
| 素材與數值 | 目前只支援 `sandbag`／`barrel`，有限座標／角度，角度 -360° 至 360° |
| 地面 | Y 絕對值最多 0.001 公尺 |
| 場地 | 旋轉後整個包圍盒在 X／Z ±6 公尺內，容差 0.0001 公尺 |
| 重疊 | 旋轉方盒四軸 SAT，有超過容差的正面積重疊即拒絕；貼齊的連續沙包允許 |
| 出生點 | 五席均使用 `ArenaSession.Spawn`，以真正 `ArenaWalkSurface` 的 0.3 公尺通行規則核對 |
| 初始敵軍 | 與真正初始規劃共用 0.75 公尺有序候選網格；單房需求為全部數量，全館為每房最多 ceil(總數／5) |

沙包仍為 2 × 0.9 × 0.7 公尺、油桶 0.7 × 1.2 × 0.7 公尺的粗略方盒，與 [FIELD_PROPS](FIELD_PROPS.md) 的視覺模型有所差別。本功能不改碰撞／命中／移動規則，不代表掩體間所有通道可通行、所有區域相互可達或具備良好戰術設計。容量是初始空世界的出生候選數，不能保證運行中增援有空位，也不是 FPS／25 台效能承諾。

共用檢查唯一來源為 `com.vrcommand.simulation/Runtime/ArenaLayout.cs`；Core 明確參考 .NET Standard 2.1 的 Simulation。Unity 保持不參考後端，舊 `ArenaSession`／世界回放不套用新的拒絕政策。建立場次先確認權限與已接受 request key，才檢查新配置；舊版曾接受的場次與已接受的原樣建立重試不會被新規則改寫或重新建立。未接受的檢查失敗不消耗 key，也不占房。事件 envelope 6／任務 schema 1／世界 schema 1／NGO 19 皆不變；新增報告不寫入舊事件。

API：

- `POST /api/mission-layout`：Master 專用，body 為 `{ experienceMode:"VR", mode:"Independent", enemyCount:8, props:[...] }`，純計算且不保存任務。
- `GET /api/missions/{id}/layout?mode=Independent`：明確 Actor 的共用任務範本讀取政策，省略 mode 預設 Independent；不是場次管理授權。
- `POST /api/sessions`：無效新 VR 配置回 400 `{ error, layout }`，其餘既有 401／403／409 權限與衝突規則保留。

報告含 version／profile／rulesVersion／mode、applies／canStart、場地與出生位、每房候選容量／需求及問題。每個問題的 `propIndex`／`otherPropIndex`／`seat` 為零起算，沒有對象為 -1；UI 顯示時加一。最多 500 個物件，僅傳前 128 個問題，`totalIssueCount` 保留完整數量、`truncated` 明示，`invalidProps` 仍列出全部涉及索引。無效數值／越界物件不進一步參與容量推算，容量為 null，不能當作通過。

管理包 0.31.245 在保存版本的場地報告及建立場次的場地拒絕回應中提供 `missionId`。準備區會比對選取的版本與回應，再顯示檢查結果。版本未核對時，該房等待重新檢查，建立按鈕保持停用。五房逐房指定時，仍可查看其他房間已核對的圖。草稿試算沿用原本的配置請求與報告。

草稿與保存版本各有請求序號、登入 epoch 及精確內容／選擇核對。舊回應不得改寫新草稿、切換模式後的批准或登出後的畫面；快取僅本次登入、以不可變版本與模式索引。憑證仍限頁面記憶體。API 和控制台須一起更新至 v0.18，不能以舊 API 的無檢查建立當作相容解法。
