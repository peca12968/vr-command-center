v0.13 已加入頭手來源 byte／追蹤狀態檢查、世界來源、共用發布及管理邊界錄製，詳見 [WORLD_SOURCE.md](WORLD_SOURCE.md)。該版 NGO protocol 13 為歷史；現行兩端使用 protocol 18 並保持同版場景識別。

本版把共用戰鬥核心接到 Unity 的任務、入場、姿態、武器及 NGO 狀態同步來源碼。**已通過真正 Unity 編譯／建置及 PC 雙玩家連線、AI 傷害與封存，已有 PC GPU 視窗與鍵鼠射擊／擊殺證據，仍沒有頭盔射擊或 25 台效能證據。** .NET、無圖形 PC 及頭盔驗收分別記錄。

## 同一套任務與戰鬥規則

`Packages/com.vrcommand.simulation/Runtime/ArenaSession.cs` 是無 Unity／後端相依的伺服器接入層，使用 field DTO 讀取真實 SessionView JSON。它建立 ArenaWorld、固定出生席位、管理名冊及連線綁定，套用執行階段、AI 行為、自動攻擊、能見度與日夜。v0.11 另新增戰鬥來源 API 與持久補送，見 TELEMETRY。

只接受 Preparing 時啟動遊戲伺服器；Running／Paused／Ended 不能以全新世界代替恢復，避免重設血量、彈藥及敵軍。管理快照不能換場次／任務、倒退序號或修改幾何。Preparing 的名冊變更可重新建立尚無戰鬥的世界；開始後只能撤銷既有玩家，不新增身體。伺服器崩潰的持久世界恢復尚待開發。

目前支援 VR、平坦 12m × 12m 房間、地面沙包／油桶。任務擺設在每個參與房間複製，以固定 ID、同一尺寸與旋轉提供碰撞及渲染；未知資產、非地面高度、超出場地或擋住出生點的設定明確拒絕。2D 編輯器可保存更廣的資料，並不保證全部適用此垂直切片。MR 會拒絕，不能把 VR 光照當成透視或場地校正。

敵軍設定 count 是全場總實例數（最多 100），平均分配到參與房間，從未被掩體占用的候選點選取出生及巡邏端點；不是每房再乘一次 count。減少數量移除尾端實例，增加時產生新的生命 ID；已死實例保持死亡，不因例行刷新復活。尚無玩家指定敵軍出生／巡邏點、群體避讓或複雜地形。

## 輸入與連線

桌面遊戲伺服器先向管理 API 驗票，再把連線 ID 綁定名冊玩家／房間／席位。頭盔不能在 RPC 選擇玩家 ID、命中目標、傷害或彈藥。相同玩家同時只可綁定一條連線；斷線移除綁定、保留既有身體的血量／彈藥，新連線使用獨立輸入序號域。

姿態檢查共用場地／掩體及頭口距離規則，另以伺服器收件時間拒絕倒退／非有限時間與超大平面位移。容許位移為 0.5m 加每秒 4m 的時間量，時間差最多計 0.5 秒；這是粗略異常防護，尚非完整防作弊或延遲補償。連線須先送有效姿態才參戰，超過 0.5 秒沒有新姿態會移出碰撞、射擊與 AI 目標集合；有效姿態抵達後可恢復，血量／彈藥不重設。

Quest 來源碼使用 OpenXR 右手 pointerPosition／pointerRotation 瞄準、右扳機射擊、右手 A 鍵換彈。要求 Floor tracking origin；若尚不能使用 Floor，暫用 1.65m Device offset。仍須實機驗證追蹤原點、重置與空間校正；這不是實體場地定位方案。桌面 Client 使用 WASD、右鍵拖曳轉向、左鍵射擊、R 換彈，只供開發預覽。未校正或走出支援區域時，頭盔畫面不能被當作有效戰鬥姿態。

可靠 owner RPC 傳送武器意圖及當下姿態，20 Hz 姿態 RPC 使用不可靠傳輸。伺服器仍執行射速、彈藥、換彈、健康與最近射線碰撞判定。輸入序號重送／倒退不再次扣彈；舊連線的輸入與斷線通知不能影響後來的綁定。

NGO 2.7 的 HostServerInitialize 不等待非同步 Host approval，來源碼因此先向 API 驗 Host 票券，再同步回答本機入場。專用 Server 不占玩家席位，建議優先測此模式。Host 玩家被撤銷時關閉整個 Host；其他遠端玩家被撤銷則斷開該連線。非同步驗票完成後也確認該 pending client 尚存在，避免斷線後保留幽靈綁定。專用 Server／兩個遠端 Client 已通過本機 smoke；Host／撤銷競態仍待獨立原生驗收。

## 場景、同步與顯示

ProjectBuilder 生成地板及戰鬥元件，不再放入未經核心判定的展示掩體。CombatAuthority 在伺服器以目標 20 Hz 推進世界；單幀最多追趕 0.2 秒，避免長停頓造成無界追趕。管理快照每次成功更新新鮮度，超過 1.5 秒沒有新資料會暫停戰鬥；重新取得相同序號快照也能從暫停恢復。

擺設及角色由伺服器寫入 NetworkList，供初始加入及後續狀態更新；角色目標更新 10 Hz，只寫變動值，客戶端平滑敵軍位置。模型仍是簡單盒／膠囊、頭部／雙手及武器盒；不代表正式軍事美術、動畫或射擊音效。HUD 顯示目前階段、伺服器血量、彈匣／備彈、換彈及追蹤異常；死亡／無效參戰角色隱藏。

這些同步頻率是來源碼目標，沒有實際頻寬、幀率、延遲、封包遺失或 25 台結果。每個遊戲伺服器對應一個 Independent 或 Linked 場次，五個獨立遊戲伺服器需不同 UDP 埠；尚無自動程序調度。

## 戰鬥統計管道與仍待接入的回放

v0.11 的 Unity 來源碼會把四種統計 WorldEvent 保存到共用 TelemetryOutbox，綁定有序來源後批次送入 API，並於 End 補送／封存。相同 journal 及後端已通過跨程序 .NET／HTTP 驗證，且真正 Unity PC 發送器已通過 AI 傷害與封存統計整合；仍不能宣稱頭盔 HUD 與主控台數值已實測一致。預設標記 Simulation，詳見 TELEMETRY。

持久 outbox、Pause／End 補送及封存邊界已實作，接續仍須原生故障／實機驗收、量測與損壞檔恢復流程。世界／頭手來源已保存並由 PC 合成頭手完成補送／封存，實際頭盔追蹤與操作者完整事件仍須分別驗收。瀏覽器維持既有 schema 2／rules 0.8.0 合成紀錄，不把此管道當作頭盔錄製驗收。

## 已執行與待執行的驗證
