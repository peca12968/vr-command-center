# 持久世界錄製與觀察 v0.16

## 載入較早錄製

管理包 0.31.147 的「觀戰與任務回放」先顯示最近 30 筆可讀取的錄製。使用中的場次有錄製時也會出現在清單。按「載入較早錄製」可逐頁往前查閱，並保留當前選取與播放位置。按「更新錄製列表」可回到最新一頁，仍可選用原本選取的錄製。

從房卡、任務收尾、全館收尾或戰績開啟觀戰與回放時，控制台直接要求原場次。原場次在第一頁以外時也會出現在清單，日後翻到原場次所在頁面只顯示一筆。

`GET /api/world-recordings/page` 依場次建立順序由新至舊回傳 `recordings`，預設 30 筆，`limit` 可設 1 至 50。以回應的 `nextBefore` 作為下一頁的 `before`，讀取更早的場次。可重複傳入 `include` 指定至多六個原場次 ID。這些場次及第一頁以外的使用中錄製會透過 `pinned` 回傳，並套用相同的房間讀取權限。既有 `GET /api/world-recordings` 保留完整陣列格式。

## 從房卡或全館收尾開啟

Windows 管理包 0.31.38 起，使用中的房卡提供「即時觀戰」。控制台直接連到該房當前場次，從該房俯視開始。合併場仍可用原有的房間切換與自由鏡頭查看其他角度。

管理包 0.31.117 的合併場房卡也提供「僅接收本房資料」。房控從此入口開啟時，服務只傳本房的場景物件、角色、敵軍、戰鬥事件與統計。觀戰、回看、逐格及重連沿用此房，畫面仍可移動鏡頭。共用觀戰可從原「即時觀戰」按鈕開啟。

此入口在 `/world`、`/world/watch` 與 `/world/frames/{sequence}` 傳入 `observerRoomId`。服務保留原場次、串流識別及畫格序號，並回傳實際投影房號。房控只能指定自己的房間。省略參數使用共用錄製檢視。

管理包 0.31.219 在顯示單房錄製前核對場景物件的房號與位置。即時串流、回放及逐格讀取也核對戰鬥事件的玩家與有射線事件的起點。資料超出選定房間時，控制台顯示讀取失敗並保留上一格；重新連接仍使用原房。

主控在「最近一次全館收尾」可直接按「回放原場次」。控制台核對原場次、錄製來源及封存尾端，從第一格播放。獨立場從原房俯視開始，合併場從全場總覽開始。若原錄製仍未封存但已有保存資料，可按「回放已保存片段」，從第一格播放到收尾表確認的最後一格；之後可使用原有的「檢查新保存快照」。

房間重用後，收尾仍開啟原場次。若原錄製暫時無法取得，畫面會保留未選取狀態並提示重試。`GET /api/venue/closure` 在有可讀取資料時提供 `replay.streamId` 與 `replay.throughSequence`，供控制台核對播放來源與界線。

Windows 管理包 0.31.80 可從全館收尾直接回看原有效姿態開場。回放停在原準備中畫格，並顯示該格的合成和追蹤席數。 [回看有效姿態開場](SESSION_CLOSURE.md#回看有效姿態開場)

### 從單一場次的任務收尾回放

管理包 0.31.143 可在「房間與場次」選取已結束的場次，從「任務收尾」按「回放原場次」。房控在合併場和獨立場都會從本房俯視開始，接收本房的場地物件、玩家、敵軍、事件及統計。主控可看合併場全景。

若錄製還在等待封存，已有確認的快照時會顯示「回放已保存片段」。控制台從第一格播放到點選時已確認的最後一格。若場次或錄製來源無法確認，請等收尾狀態更新。房間已用於新場時，仍可從歷史場次回放原錄製。

### 對齊同批獨立房間的回放

管理包 0.31.93 的主控可從「全館收尾」開啟原獨立房回放，暫停在要檢討的畫格，再從「同批房間回放」選另一房。從已封存的開場見證進入時，也可直接用目前停留的畫格對齊。目標房間會停在該房原錄製中，擷取時間最接近且早於或等於原畫格的一格，並顯示時間差。

連續切房會保留第一次選定的擷取時間。逐格移動、拖曳時間軸或繼續回放後，下一次切房會用新的畫格時間。只有同一結案批次中已封存、帶 UTC 擷取時鐘的獨立房間會出現在選項內。時間未重疊或畫格差超過 500 毫秒時會保留目前畫面。跨機比較的準確度取決於伺服器時鐘同步。

對齊使用主控唯讀的 `GET /api/venue/closure/{id}/replay-at`，以 `fromSessionId`、`fromFrame` 和 `roomId` 指定原畫格及目標房間。合併場沿用同一錄製的房間切換。

控制台 0.31.125 在同一區域提供「任務活動時間」。兩個獨立房即使在不同時段開場，也可依錄製中的遊戲刻數對齊。每秒 20 刻，暫停期間會保留原刻數。目標房使用最接近且不晚於基準的有效刻數，最多早 10 刻。同一刻有多格時，會停在目標房最先保存的那一格。返回基準房會回到原畫格。

原房與目標房須來自同一結案批次，各自完成戰鬥與世界封存，並含任務時鐘。基準畫格須有正數的任務刻數。目標房尚未錄到指定活動時間、沒有符合範圍的畫格，或錄製來源不符時，保留目前畫面。擷取時間仍是有 UTC 資料時的預設。切換對齊依據、逐格或續播會重設比較基準。鏡頭操作尚待確認時，兩種對齊都會等候原操作結束。

活動時間使用唯讀的 `GET /api/venue/closure/{id}/replay-at-tick`，參數同上，回應含原畫格與兩邊的刻數。服務按已驗證為非遞減的原刻數搜尋，沿用原錄製及管理權限。 [Windows 原生驗收](PROGRESS.md)

API0.30新增[來源連線公告](EXTERNAL_CLIENTS.md)：worlds.db的connection_endpoints保存session／stream／owner綁定的不可變地址／port，GET供控制台、PUT限GameServer owner且world header已存在。原header／世界schema1不變，公告不是連通性或戰鬥授權。

API0.29新增唯讀[玩家參戰快照](PLAYER_READINESS.md)，以最後接受幀的Observed入場核對當前名冊，回報擷取年齡與狀態、不傳頭手座標。世界schema／歷史及原始header不變；GameServer不能使用此控制台診斷。

2026-10-31 新來源另有combatAudioVersion1，缺失保持0；只依已接受的玩家／敵軍fire witness重建短聲音，不保存或宣稱原始音軌。新版本、音效gesture、跳轉／過期抑制及NGO25協同更新見 [COMBAT_AUDIO](COMBAT_AUDIO.md)。world schema1與原binary checksum保持，schema相同不代表可降舊reader。

2026-10-31 最新換彈／合成手套為API／UI0.21、Unity0.23／code26／NGO22；weaponPresentationVersion1及weapon-actions-v1需來源／API／UI／全體遊戲端一起更新，舊資料保持0／舊外觀，不可降舊reader。保存時鐘、Tracked界線及實際證據見 [WEAPON_ACTIONS](WEAPON_ACTIONS.md)／PROGRESS。

2026-10-30 最新人形敵軍接入為API／UI0.20、Unity0.22／Android code25／NGO21，header enemyPresentationVersion1及combatants-v1需協同更新；舊來源／外觀保留，不能降舊reader。保存姿態、原命中盒與限制見 [ENEMY_PRESENTATION](ENEMY_PRESENTATION.md)，真正建置／PC結果以 PROGRESS 為準。

管理主控台的「觀戰與任務回放」讀取遊戲伺服器已接受的世界資料。世界發布走 WebSocket，觀察及回放走帶 Bearer 的 fetch SSE；逐幀遊戲輸入仍由 NGO 處理，不使用管理 REST。觀察者不加入玩家名冊。既有「3D 模擬回放」仍用本機 schema 2 檔案；兩種格式及來源不可混為一談。

目前另有 **真正 Windows Unity → 共用來源／WebSocket → SQLite → SSE → 控制台即時觀戰／鏡頭與回放** 證據，見 [DESKTOP_CONTROL.md](DESKTOP_CONTROL.md)／PROGRESS。瀏覽器為 Chromium 軟體 WebGL；原生玩家 GPU 白天／雨夜／Pause 另行檢視。來源明確 Simulation、頭手合成，不是頭盔錄影或 Quest 驗收。原 v0.13 未編譯／授權問題僅為歷史，最新真正建置見 WORLD_SOURCE／NATIVE_VALIDATION。

## 操作

1. 啟動新版 API／主控台。用 Master 或所屬 Room 憑證登入，選「觀戰與任務回放」。
2. 更新錄製列表，選場次；列表標示房間、來源及是否完整。
3. 「即時觀戰」只取最新已保存快照；拖曳旋轉、Shift／右鍵平移、滾輪縮放，或用全景／上帝俯視／跟隨鏡頭。房間與角色可以選取。未參戰／死亡角色降低透明度。

### 從觀戰頁切換目前房間

控制台 0.31.129 的主控可直接選取觀戰頁上方的房間，開啟該房的即時上帝俯視。獨立房間會切到該房自己的錄製，合併房間沿用同一場次，只讀取選定房間的角色、場地及統計。

房間列隨「更新錄製列表」更新。尚無已保存畫格的場次會顯示「等待可觀戰錄製」。切換前，控制台再核對原房間是否仍屬該場次及錄製來源是否相符。核對失敗時保留目前畫面，可更新列表後重試。已結束場次從錄製選單或收尾紀錄進入回放。

管理包 0.31.192 先讀取並核對目標房的保存快照，再切換畫面。若目標快照讀取失敗或含其他房間角色，會保留原房畫面。切換後若新串流中斷或來源不符，畫面會保留目標房已核對的快照並標示最後保存格。

從 0.31.193 起，分房觀戰中斷後可按「即時觀戰」重連原房錄製，保留鏡頭及最後已核對畫格。自動與手動重連都會拒絕較舊的畫格；分房串流每格也會核對角色、敵軍設定及玩家統計的房間。

要用原生 Windows 套件重跑觀戰驗收，可在三包驗收命令加入 `--prepare-independent-set --check-venue-begin --check-venue-end --check-venue-launcher --check-venue-plan-ui --check-live-room-navigation`。測試逐房核對實際串流、上帝俯視及同一格的玩家統計，結束後再讀取原畫格與統計。加入 `--check-room-reports --check-room-combat` 可在切房前先產生遊戲內受傷資料。 [三包命令](WINDOWS_SERVER_PACKAGE.md)

多房錄製的畫面上方有「全部房間」和各房按鈕。0.31.121 顯示此格有有效頭手姿態的存活玩家數，以及存活敵軍數，分母為此格的角色總數。角色資訊會標記此格有效姿態、姿態未同步、無頭手資料或已淘汰。這些標記來自已保存的畫格。選房會移到該房並篩選玩家統計與逐格事件。全景及俯視保留目前角度設定，套用精確座標或書籤時回到全部房間。

控制台 0.31.50 也會按房間篩選角色選單及場景角色點選。玩家名稱取自目前已接受快照的統計。切房後可選本房角色跟隨。跟隨對象若從新快照消失，畫面會在最後位置切回自由鏡頭，等候重新選擇。切回全部房間可查看完整角色清單。 [開發進度](PROGRESS.md)

控制台 0.31.90 可在「此快照已核對的統計」按玩家列的「跟隨」，或聚焦該按鈕後按 Enter。鏡頭以目前房間範圍內的原玩家為目標，保留正在使用的錄製來源。統計更新時，仍在表中的同一列會保留鍵盤焦點。若玩家只剩歷史統計而當前快照已無角色，該列的按鈕會停用。切房時，跟隨不會自動改選別的玩家。

4. 「從頭回放」按保存時間播放，不重新執行 AI。支援 0.25–4 倍速、暫停及時間跳轉，透過 SQLite 時間索引取前一份快照，不下載整場檔案。角色資訊顯示頭手來源 None／Simulated／Tracked。
5. 統計由各快照的已驗證事件前綴計算。以擷取時間計算超過 1.5 秒或串流中斷即顯示過期；SSE 心跳／補送不重設年齡，沒有時間標示未知，來源時間超前標時鐘未同步。Ended 及未封存仍可能同時存在。
6. 調整鏡頭後輸入名稱，按「保存目前位置」；從已保存位置選單按「切換位置」恢復固定世界目標、水平／垂直角度及距離。跟隨鏡頭保存的是當下位置，不會保存持續跟隨行為。相同控制台身分重新登入後，可在同場即時觀戰或回放讀回位置；不同場次或身分不共用。可移除位置，每個身分每場最多 24 個有效位置。

鏡頭設定與遊戲控制分開：保存／移除位置不改變世界幀、戰鬥事件或玩家名額。保存／移除回應遺失或 5xx 時凍結原 ID、位置及名稱，按「重試確認結果」原樣確認；等待期間可調整視角，但不能用新視角取代原請求或切換錄製場次。單次寫入等待最多 10 秒；登出／關閉頁面會失去待確認請求，再登入後應先讀取已保存位置確認結果。已接受後又被其他視窗移除的保存請求，重試回 Deleted 而不重建位置。名稱以 textContent 顯示。

切頁、換場或登出會取消當前串流，舊回應不能恢復場景。所有文字採 textContent，不執行任務／玩家名稱內的標記。憑證只在頁面記憶體及 Authorization 標頭，不放 URL、localStorage、sessionStorage 或 cookie。

### 從即時觀戰回看最近 10 秒

控制台 0.31.68 在即時觀戰畫面提供「回看最近 10 秒」。終點是按下時畫面上已顯示的保存格。回放從十秒起點或之前最接近的保存格開始，錄製還不到十秒時則從第一格開始。即使遊戲繼續進行，本次回看的終點仍維持原格。到尾端後可暫停逐格檢視、查看當格戰鬥事件及統計。

按「返回即時觀戰」會接回同一錄製的最新快照，保留目前的房間範圍與鏡頭。若原跟隨角色在回看時消失，沿用自由鏡頭的最後位置。換場、離開頁籤或登出會清除這次回看的返回操作。

### 從即時觀戰定位最近設定

管理包 0.31.155 在即時觀戰提供「定位最近設定」，預設查找環境變更。也可選場次階段、敵軍策略、敵軍增減、首格狀態或全部設定。按下時固定目前畫面上的保存格，沿用所選房間搜尋該格及更早的保存格。找到最近一筆設定後暫停在原畫格，並保留房間及鏡頭。沒有符合的設定時會停在按下時的畫格。

按「返回即時觀戰」可接回同一錄製的最新快照。查找和回看期間，遊戲伺服器仍持續發布。暫停後可沿用選定種類逐筆跳轉，搜尋範圍仍以剛才確認的尾端為限。

### 從即時觀戰定位最近事件

控制台 0.31.135 可在即時觀戰選擇事件種類並按「定位最近事件」。控制台把目前已顯示的保存格固定為尾端，在原錄製與所選房間中往前找，停在最近一格符合的事件，顯示該格戰況與統計。若目前格已相符就停在該格；若沒有相符事件，會保留原格並顯示搜尋結果。

主控可用「全部房間」搜尋合併場，或先選房後只找該房。已用房間入口開啟的觀戰沿用同一房間範圍。按「返回即時觀戰」會接回同一錄製並保留鏡頭。這個操作只讀取已保存的錄製，遊戲照常進行。

### 即時觀戰斷線後重新連接

控制台 0.31.213 在已確認錄製來源後，遇到串流斷線或連續 6 秒沒有收到快照或服務心跳，會在 20 秒內嘗試重連，最多八次。前三次約間隔 0.5、1、2 秒，此後約每 3 秒再試。畫面保留原房間、鏡頭及最後已顯示的快照，並標示快照過期或連線中斷。收到同一錄製的新一格才恢復更新。錄製來源不符或重試用完時，可用「即時觀戰」手動連接。

換場、切換至其他頁籤、登出或開始回放會取消待執行的重連。健康的服務心跳只維持串流連線，快照的新鮮度仍依原擷取時間顯示。

0.31.121 在即時串流中斷、畫格過期或擷取時間無法確認時，會標示「顯示最後保存格」。串流先核對標頭，再接受同一來源與房間範圍的狀態及封存訊息。即時狀態若回報較舊的序號或撤回已接受的封存，觀戰會停止接收該次串流並保留原畫面供檢查。

控制台 0.31.232 手動重連同一錄製時，全景與分房皆核對原來源及最後確認的畫格序號。從即時回看返回時，仍以回看前最後接受的即時格為下限。服務若只回應較早畫格，畫面留在目前位置並提示重連。服務再次提供原即時格或較新格後，可恢復觀戰並保留鏡頭。主動選取不同錄製會重新建立比對範圍。

### 暫停逐格檢視

控制台 0.31.9 可在回放暫停後按「上一格」或「下一格」，讀取相鄰的保存快照。逐格區顯示該格保存的射擊、命中、擊殺、受傷及換彈事件，也保留原序號、相關玩家、房間與當格統計。沒有事件的快照會明確顯示空白原因。續播會從目前的快照序號開始，同一毫秒有多份快照時也可依序檢視。

控制台 0.31.188 可在暫停時輸入「畫格序號」，按 Enter 或「跳到畫格」。畫面會停在指定格，保留目前房間、鏡頭和玩家檢討範圍。未封存錄製的上限為本次確認的保存尾端。切換錄製會清除輸入。

單格使用 `GET /api/sessions/{id}/world/frames/{sequence}`，依原場次讀取權限回傳該快照及統計。回放串流可用 `mode=replay&fromFrame={sequence}` 明確指定第一格，此參數與 `fromMs` 擇一。第一格與已接受的最後一格限制逐格範圍。換場、離開頁籤或登出會取消逐格請求。 [驗證紀錄](PROGRESS.md#2026-11-06-任務回放逐格檢視)

原生 Windows 短場可用 `scripts/check-desktop-exercise.py --check-frame-review`，把單格射擊事件、續播前兩格、分房與逐席事件搜尋及同發射擊結果與同場完整保存回放逐欄比對。 [自動操作驗證](DESKTOP_EXERCISE.md)

### 追查同發射擊

控制台 0.31.108 可在暫停回放時，從玩家射擊、命中敵軍或擊殺敵軍事件按「追查同發射擊」。清單依原射擊 ID 顯示已保存的發射、命中及擊殺事件，並列出各自的畫格及房間。點選其他畫格前，控制台會核對該格的事件、玩家、射擊 ID 與房間。追查及跳格會沿用目前的房間和個人檢討範圍。

未封存回放以本次確認的保存尾端為限。清單尚未出現命中或擊殺時，只代表查詢範圍內沒有對應的保存事件。更換房間、檢討玩家或錄製會清除查詢結果。

唯讀端點 `GET /api/sessions/{id}/world/shot-trace` 使用 `fromFrame`、`throughFrame`、`eventId` 及選用的 `roomId`。`fromFrame` 是所選事件的畫格，結果也可包含該格之前的同發射擊事件。房控只能查詢本房。服務由原戰鬥報告找到同發射擊，再依保存畫格的戰鬥序號定位。回應使用 `Cache-Control: no-store`。

### 查閱錄製中的設定切換

使用 0.31.98 與 0.50.0 錄製的合併場可在單房視角查看該房的實際敵軍策略。單房設定清單會依保存畫格列出覆寫與恢復後的有效策略，指定房間的玩家回放匯出也保留該房的有效策略。 [分房設定](LAYOUT.md#合併場分房敵軍策略)

控制台在暫停回放後提供「錄製中的設定切換」。可從第一格或目前格開始查閱。清單列出首格狀態，以及場次階段、天氣、日夜、閃電、敵軍策略或自動攻擊出現差異的原始保存格。合併場使用原錄製的全場設定，獨立房則查閱各房自己的錄製。

從 0.31.96 起，清單另依目前觀看的房間或全場顯示在場、存活、增援與撤除人數。敵軍識別碼加入或離開名單時會列出變更。敵軍被擊倒後若仍在名單，反映在存活人數。點選清單的一格時，控制台會核對保存畫格的名單和存活人數，然後保留房間與視角跳到該時刻。

管理包 0.31.153 可在「設定種類」選取「環境變更」，再從第一格或目前格查閱。也可單獨選場次階段、敵軍策略、敵軍增減或首格狀態。更換種類會清除上一組結果與查閱位置。點選結果時會核對該格的階段、天氣、日夜、閃電、有效敵軍策略與名單，確認後保留目前房間及鏡頭並跳轉。

管理包 0.31.154 可從目前畫格按「上一筆設定」或「下一筆設定」，跳到符合目前種類的最近原畫格。搜尋從目前格的前一格或後一格開始，沿用房間及原保存範圍，跳轉後保留鏡頭。搜尋會接續查閱中間的空白區段。找不到符合畫格時，會留在目前畫面並顯示結果。

清單比較相鄰的已保存畫格。若兩格之間曾有多次變更，清單顯示下一個實際保存的狀態。未封存的回放依本次固定尾端查閱。換房、換場、切頁或登出時會清除結果。

唯讀端點 `GET /api/sessions/{id}/world/policy-frames` 需要 `throughFrame`，可用 `afterFrame` 指定不包含的游標。每頁最多查閱 1,024 格並回傳最多 24 格，`nextAfterFrame` 非空時可繼續。傳入 `includeEnemyRoster=true` 可取得名單與變動量，並可用 `roomId` 指定錄製涵蓋的房間。權限沿用原錄製。原生設定變更可用 `scripts/check-desktop-exercise.py --operator-controls --check-policy-frames` 核對，原生增撤援可用 `scripts/check-server-package.py --check-live-reinforcement` 核對。

選填 `change` 可只回傳符合 `initial`、`phase`、`suspension`、`environment`、`enemies` 或 `enemy-roster` 的原畫格。`enemy-roster` 需搭配 `includeEnemyRoster=true`。回應會回傳使用的種類。若這一頁沒有符合的畫格，仍可依 `nextAfterFrame` 繼續查閱原保存範圍。

控制台 0.31.172 可在即時觀戰與回放選取「遊戲來源暫停／恢復」。搜尋依原畫格的 `suspended` 狀態變化，標出進入暫停的第一格及恢復執行的第一格。操作員手動暫停仍可從「場次階段」查閱。舊錄製缺少此欄位時以未暫停讀取。

`GET /api/sessions/{id}/world/policy-neighbor` 使用同一範圍與篩選，另須指定 `fromFrame` 及 `direction=previous` 或 `direction=next`。每次最多查閱 1,024 格，回傳最近一個符合的畫格。即時觀戰首次向前回看時加上 `includeFrom=true`，將畫面上的尾端也納入搜尋。空白區段可依 `nextFromFrame` 接續，後續查詢省略 `includeFrom`。往前搜尋時，每格仍與錄製時間上早一格比較。

### 重看指定片段

控制台 0.31.95 在暫停且目前畫格符合戰鬥事件篩選時，可按「標記事件前後各 5 秒」。起訖取自原錄製，包含目前事件，依已保存範圍縮短，最多 300 格。標記完成時畫面停在事件格，再按「播放指定片段」即可重看前後過程。播放沿用目前房間、鏡頭、玩家及事件種類。附近只有一格或讀取失敗時會保留原標記。

`GET /api/sessions/{id}/world/frame-context` 接受 `centerFrame` 及固定的 `throughFrame`，回傳原場次、串流及中心和起訖畫格。時間採錄製內的經過毫秒。起點和終點各取範圍內最外側的保存畫格。查詢沿用原錄製權限，回應使用 `Cache-Control: no-store`。

控制台 0.31.59 可在「逐格檢視」標記片段。暫停後，以時間軸、逐格按鈕或事件搜尋定位第一格，再按「將此格標為起點」。到較晚的一格按「將此格標為終點」，即可從起點播放到指定終點，兩格都包含在內。播放期間可暫停，再用原回放按鈕繼續。要重看整段，可再按「播放指定片段」。

標記顯示保存格序號及其時間。片段播放沿用所選房間、鏡頭與個人檢討條件。播到終點並讀到串流尾端確認後才顯示「已到片段終點」。暫停後改用逐格或事件跳轉，或移動時間軸，可繼續檢視原錄製。未封存錄製沿用當次已確認的保存範圍，仍可在原保存尾端接續。標記只在目前的回放頁保留，換場、開啟即時觀戰或離開頁籤時清除。

管理包 0.31.159 可在片段有起訖後勾選「循環播放片段」。每次核對終點後，播放會短暫停在終點，再回到原起點。暫停可停住目前畫格。取消勾選時，正在播放的這一輪會播到終點，已停在終點等待重播時則直接停下。串流中斷會停止循環，可手動重新播放。換場、返回即時觀戰或離開頁籤時會清除循環選項。

控制台 0.31.107 可在標記起訖後按「讀取片段戰績」，核對兩格之間的耗彈、命中、擊殺、中彈及耗損。起訖格都計入。結果按房間及玩家分列，沿用目前房間和個人檢討範圍。每次最多核對 300 個已保存畫格。房控只可核對本房，主控可核對全場或選定一房。

管理包 0.31.116 的耗損以實際扣除的生命值計算。若玩家剩 50 點而原事件記錄 90 點傷害，事件仍顯示原始值，片段與最終戰績只計實際扣除的 50 點。舊錄製的超額耗損會在讀取戰績時修正，並可用原有封存條件核對。

片段命中率以片段內發射的射擊為分母，只計同房且在片段內確認命中的原射擊 ID。片段開始前發射的射擊仍可在命中發生時列入命中數，沒有發射時命中率顯示 `—`。變更起訖、房間或檢討玩家會清除原查詢結果。

`GET /api/sessions/{id}/world/clip-statistics` 使用 `fromFrame`、`throughFrame`，可加 `roomId` 與 `playerId`。回應包含原錄製識別及查詢範圍，使用 `Cache-Control: no-store`。範圍沒有戰鬥事件時回傳空列。

控制台 0.31.126 另顯示實際計入片段命中率的射擊數，並可下載同一已核對範圍的 CSV。 [下載片段戰績](REPORTS.md#下載指定片段的戰績)

### 保存共用片段

控制台 0.31.60 可把目前的起訖標記命名保存。主控在「已保存的共用片段」輸入名稱，按「保存目前起訖」。可讀取原錄製的房控也能選取該片段，按「載入片段標記」後再按「播放指定片段」。片段使用原錄製的兩個保存格及其時間，房間、鏡頭與個人檢討條件沿用各人目前的選擇。若片段晚於目前固定的未封存尾端，請重新開啟錄製後再載入。

每份錄製最多保留 24 段共用片段。主控可移除共用清單中的項目，原始錄製仍可播放。重新登入及管理服務重啟後可讀回清單。若儲存或移除結果尚未確認，可在同一錄製按「重試片段操作」沿用原請求。切換錄製或離開回放頁後，可重新讀取清單確認目前結果。

### 讓玩家開啟回放

錄製封存後，主控在「已保存的共用片段」選取一段已保存的片段，按「下載玩家回放檔」。每份可包含 2 至 300 個連續保存格，大小最多 8 MiB。較長片段可另外標記起訖並分段保存。合併場預設為全場，控制台 0.31.75 起可在「玩家回放範圍」指定房間。檔案不含入場票券、操作憑證、名冊姓名或戰績明細。

分房檔保留同一段原始畫格序號、時間及場次識別，只含該房的物件、角色及可確認屬於該房的戰鬥事件。含未確認或其他房間參照的事件會省略。全場累計序號從分房檔移除。玩家頁會標示房號並只顯示該房視角。

管理包 0.31.221 的網頁及離線播放器在開啟分房檔時，也會核對場景物件與射線起點的位置。若位置超出該房範圍，播放器會指出房號及問題，請從場館重新取得該片段。

主控可在原 `player-replay.json` 下載端點加上 `?roomId=3` 取得指定房間的版本 2 檔案，檔名尾端為 `-room-03.json`。未指定房號時仍取得原版本 1 全場檔案。兩種檔案都可用新版玩家頁播放。

將 JSON 檔交給參與檢討的玩家，並提供管理服務的 `/console/player-replay.html` 網址。玩家在頁面選取檔案即可逐格或依原錄製時間播放，可調整速度、拖曳鏡頭、縮放及切換房間俯視。播放器在瀏覽器內讀檔，無須登入或上傳檔案。已交付的本機副本可持續開啟，請依場館的檔案交付規範處理。

需要離開場館後觀看時，將單檔播放器 HTML 和原匯出的 JSON 一起交給玩家。用支援 WebGL 2 的桌面瀏覽器開啟 HTML，再選取 JSON 即可離線回看。播放器內含程式、樣式和 3D 素材，檔案不含任何場次資料。 [下載離線播放器](../artifacts/player-replay-follow-031226/VRCommand-Player-Replay-0.31.226.html)

Windows 管理包 0.31.190 可直接在「已保存的共用片段」按「下載離線播放器」，取得 `VRCommand-Player-Replay.html`。接著用原有的「下載玩家回放檔」取得要交付的 JSON。

管理包 0.31.191 可選好封存片段及房間範圍，再按「下載回放 ZIP」。ZIP 內含離線播放器 HTML 與同一範圍的原回放 JSON。玩家解壓後開啟 HTML，再選取同一資料夾的 JSON。只有主控可匯出場次片段。

從專案根目錄可用以下指令重建播放器。輸出須使用新檔名。

```powershell
pnpm --dir tests/browser install --frozen-lockfile
node scripts/package-player-replay.mjs artifacts/VRCommand-Player-Replay.html
```

控制台 0.31.173 的玩家回放會依保存畫格顯示任務活動時間。片段播放時間包含暫停期間，活動時間則跟隨遊戲時鐘。片段內有遊戲來源暫停或恢復時，可用「遊戲來源畫格」選單跳到該格。全場及單房檔都支援，舊檔仍可開啟。

控制台 0.31.185 的玩家頁可勾選「循環播放」。每輪在原末格短暫停留，再回到原首格，沿用播放速度和房間視角。播放中取消勾選，會播完當前這輪。若已停在末格等待重播，取消時就留在末格。按暫停、跳到指定畫格或離開頁籤都會停住播放。載入另一份回放檔會重設循環選項。

管理包 0.31.189 的玩家頁可在「畫格序號」輸入場館提供的原序號，再按 Enter 或「跳到畫格」。畫面會停在指定格，保留目前視角與循環設定。可用序號以頁面顯示的原畫格範圍為準，載入另一份檔案會清空輸入。

管理包 0.31.222 的網頁和離線播放器皆可按「戰鬥事件」篩選，使用「上一個事件畫格」或「下一個事件畫格」跳轉。同一格的多筆事件會合在一起顯示筆數，跳轉後會暫停並停在原始畫格。事件範圍依場館匯出的檔案，分房檔只讀該房，全場檔切換視角時仍可查看全場事件。

管理包 0.31.226 的「跟隨玩家」依片段第一次出現的順序，在每房用匿名編號列出角色。選取後，鏡頭在播放、逐格及跳轉時跟隨同一角色。若該格未出現這名玩家，鏡頭停在當前位置，等原角色再次出現再接回。房間視角只列出該房玩家。換房、載入其他片段或手動平移會結束跟隨。玩家編號用於辨識片段中的角色，同一人可能在不同片段使用不同編號。

`GET /api/sessions/{id}/world/clips` 回傳 `sessionId`、`streamId` 及 `clips`。主控以 `PUT .../clips/{clipId}` 送出 `streamId`、`name`、`startFrame` 和 `endFrame`，兩格都必須已保存且依序排列。兩個毫秒值由服務從原格讀取。以 `DELETE .../clips/{clipId}` 移除項目。用原識別和內容重試會得到同一筆結果，已移除的項目會回覆 `deleted: true`。資料保存在原世界資料庫的獨立資料表。

### 依房間與種類搜尋戰鬥事件

控制台 0.31.43 在「逐格檢視」提供「搜尋戰鬥事件」。暫停後，選「鏡頭、統計與事件房間」及事件種類。可從第一格搜尋，或從目前格開始，包含目前格。點選結果會停在該原始快照，畫面及統計隨快照更新，當格事件表沿用同一篩選。房間以該格保存的事件相關玩家統計判定。選「全部房間」可檢視整份快照的事件。

每頁顯示已查過的快照範圍及相符格數。同一格有多筆相符事件時，結果會列出筆數。即使這一頁沒有符合事件，只要還有保存格就可按「繼續搜尋」。搜尋未封存片段時沿用目前固定的保存尾端。換房間或事件種類會清除前一組搜尋結果。

API 使用 `GET /api/sessions/{id}/world/event-frames`。必填 `throughFrame` 為已接受的保存尾端，選填 `afterFrame` 為不含在本頁的起始游標，預設為 0。可再加 `roomId` 與 `kind`，例如 `ShotFired` 或 `PlayerDamaged`。0.31.44 可加 `playerId`（玩家 UUID）與其他篩選同時使用，回應會帶回指定的 ID。每次讀取最多 128 格及 24 個相符格，`nextAfterFrame` 非空時可用同一組條件接續。服務沿用場次讀取權限，從既有保存快照讀取事件與玩家房間。 [從戰績開啟個人回放](REPORTS.md#從戰績開啟個人回放)

「僅接收本房資料」的觀戰與回放沿用本房的搜尋及跳轉範圍。自控制台 0.31.211 起，搜尋與前後跳轉的每個相符畫格均包含按原順序排列的 `eventIds`，搜尋回應也帶回套用的 `roomId` 和 `kind`。點選結果或前後跳轉時，控制台會核對畫格時間及符合篩選條件的事件識別。核對失敗時保留原畫格。

`event-frames` 與 `event-neighbor` 接受選填的 `observerRoomId`，並在回應帶回此房號。事件按與畫格相同的規則核對玩家、敵軍、命中物件與射線。房控可指定自己的房間。同時傳送 `roomId` 時，兩個房號必須一致。共用觀戰沿用原查詢及權限。

控制台 0.31.51 在暫停回放時提供「上一筆事件」與「下一筆事件」。跳轉會略過目前格，沿用所選房間、事件種類及個人戰績篩選，停在最近的相符原始快照。若保存範圍沒有相符事件，保留目前位置。切換範圍或繼續播放時會取消這次搜尋。

跳轉使用 `GET /api/sessions/{id}/world/event-neighbor`，以 `fromFrame`、`throughFrame` 和 `direction=previous|next` 設定範圍。每次最多讀取 2,048 格。若回應帶有 `nextFromFrame`，控制台以原保存尾端接續搜尋。此操作搜尋的總期限為 30 秒。兩種搜尋均讀取既有保存資料的事件陣列，分房時再核對該格統計。 [SQLite JSON 函式](https://www.sqlite.org/json1.html#the_json_extract_function)

### 回放未封存的已保存片段

未封存錄製提供「回放已保存片段」。按下時，服務以當下已接受的最後一格固定本次範圍，播完會顯示「已到已保存片段尾端」。逐格、拖曳時間軸、倍速和續播都使用同一範圍。畫面以「快照階段」標示保存當時的場次階段。

控制台 0.31.15 在抵達未封存片段尾端後提供「接續新保存片段」。按下後查詢同一場次的已保存尾端。若來源已補送，從剛看完的下一格播放到本次確認的尾端。若沒有新格，畫面留在原位置。已核對封存的錄製會顯示封存狀態。也可以按上方回放按鈕從頭播放。

API 可在 `mode=replay` 使用 `throughFrame=latest` 固定當次保存尾端，或指定已存在的正整數序號重新開啟相同範圍。省略起點時從第一格開始。超出範圍的時間跳轉會停在片段尾端。固定範圍的串流以 `saved-end` 結束，只有範圍涵蓋服務已核對的完整錄製，才保有封存狀態。

## 可重現示範與補送

從專案根目錄執行，房間 5 必須空閒，輸出檔必須不存在。工具只建立及控制自己的 Simulation 任務，其他場次不變。

```powershell
dotnet tools/VrCommand.WorldRelay/bin/Release/net10.0/VrCommand.WorldRelay.dll --recording F:/Projects/vr-command-center/artifacts/world-demo/example.ndjson --demo-room 5 --seconds 3
```

預設服務 `http://127.0.0.1:5080`，使用忽略的 `data/operator-keys.local.json`，不輸出密鑰。可指定 `--base-url` 與 `--key-file`。`--seconds` 為 1–60 秒，逐 20 Hz 邏輯 tick 產生快照；寫入／網路耗時使實際牆鐘時間更長，這不是吞吐量或 25 台裝置效能測試。會記錄 Preparing、實際射擊／AI 傷害、Pause、Storm／Night／Lightning 設定、Ended，先確認戰鬥封存再確認世界封存。

來源檔以單行 JSON 保存 header／frame／seal，寫入後 Flush(true)，再送出並等待逐幀回應。旁邊 `.combat` 是既有 checksummed TelemetryOutbox。來源檔及 journal 都只允許獨占寫入；不儲存憑證。預設任務只有一位合成玩家，沒有頭盔連接。

原程序停止後，可以由另一程序讀同一來源：

```powershell
dotnet tools/VrCommand.WorldRelay/bin/Release/net10.0/VrCommand.WorldRelay.dll --recording F:/Projects/vr-command-center/artifacts/world-demo/example.ndjson
```

先補送持久戰鬥報告，再逐行送出原始世界資料；已接受的同序同內容只確認，不再新增。來源缺少 seal／Ended 或戰鬥未完整，不會自行製造完成。JSON 壞尾端、內容衝突會停止，不截斷／忽略損壞資料。工具目前遇到網路錯誤會退出，保留來源供手動重送；不宣稱自動重連或崩潰後世界繼續運算。來源 NDJSON 沒有簽章／逐行 checksum，磁碟／傳輸可接受性仍依賴受信任來源及伺服器驗證。

v0.13 首選 checksummed binary 世界來源，共用 Unity／.NET publisher、擷取時間與補送操作見 [WORLD_SOURCE.md](WORLD_SOURCE.md)。上述 --recording 範例保留為舊 NDJSON 相容模式。

## API 與封包

所有端點都經既有 /api Bearer 驗證及 SessionManager 房間範圍檢查。

| 路徑 | 用途 |
|---|---|
| GET `/api/world-recordings` | 只列可讀場次的錄製 metadata |
| GET `/api/sessions/{id}/world` | header、acceptedSequence、durationMilliseconds、complete、updatedAtUtc、capturedAtUtc、missionName |
| WS `/api/sessions/{id}/world/publish` | 僅綁定該 combat-stream 的 GameServer 身分可發布 |
| SSE `/api/sessions/{id}/world/watch` | 最新已保存快照；可跳過中間幀，以免慢速觀察者積壓 |
| SSE `.../watch?mode=replay&fromMs=0&rate=1` | 順序回放；rate 僅 0.25／0.5／1／2／4 |
| GET `.../world/cameras` | 目前控制台身分在此錄製場次的有效鏡頭位置 |
| PUT `.../world/cameras/{cameraId}` | 以新的非空 GUID 保存不可變位置；相同 ID／內容重試確認原結果 |
| DELETE `.../world/cameras/{cameraId}` | 移除自己的位置；原 ID 重試可確認，不復活已移除資料 |

鏡頭端點僅 Master／RoomController 可用，每次均重新檢查錄製存在及目前房間讀取範圍，GameServer／Internal 不作控制台使用。命名空間使用完整 OperatorIdentity（ID、角色、房間），不是瀏覽器或員工帳號；共用同一控制台身分的視窗共用設定，Master 也不讀取其他控制台的鏡頭收藏。PUT body 為 `{ "name": "東側沙包", "view": { "target": [-14,0.8,0], "theta": 0.6, "phi": 0.9, "radius": 15 } }`；名稱 1–60 字元、不含控制字元／前後空白；target 三個有限分量各 ±120 m、theta ±π、phi 0.06–1.5、radius 2–240 m。不同內容重用 ID 為 409；未知／他人的 ID 移除為 404，已移除的同身分 ID 重試為 204。有效鏡頭超過 24 個時新保存為 409，同 ID 已接受的重試仍可確認。回傳位置包含 id、name、view、createdAtUtc、deleted。

WebSocket 使用一般 Authorization Bearer 握手；不可將頭盔玩家票券當成 GameServer 憑證。每條新 socket 先送 header。UTF-8 文字訊息上限 1 MiB；不接受二進位或未知訊息種類。

```json
{"type":"header","payload":{"schemaVersion":1,"sessionId":"…","streamId":"…","origin":"Simulation","rulesVersion":"0.8.0","assetSet":"primitives-v1","calibration":"uncalibrated-vr","roomIds":[5],"props":[]}}
{"type":"frame","payload":{"sequence":1,"elapsedMilliseconds":0,"observedSequence":3,"throughCombatSequence":0,"suspended":false,"weather":"Clear","lightning":false,"frame":{"tick":0,"throughSequence":0,"phase":"Preparing","behavior":"Hold","visibility":"Clear","autoAttack":true,"night":false,"players":[],"enemies":[]},"events":[]}}
{"type":"seal","finalSequence":44}
```

範例只展示形狀，實際 props／players／enemies 必須符合任務，省略名冊不可發布。成功回應 `{"type":"ack","info":...}`，只在持久交易 commit 後確認。拒絕回 `type:error` 並結束 socket；斷線未收到 ack 應重送原內容。這不是逐幀事務跨 combat.db／worlds.db 的分散式交易；戰鬥前綴可以已接受，世界仍待重送。

header 綁定既有戰鬥 streamId、來源及同一 owner；房間／物件 ID、位置、旋轉與任務規範幾何逐項相同。只支援 rules 0.8.0、primitives-v1、未校正 VR，未知版本／MR 拒絕。第一幀必須 Preparing、tick 0、零事件及零戰鬥邊界。幀序號連續、時間／管理觀察不倒退，Ended 後不可續錄新幀；已接受的歷史幀仍可確認。

每份快照包含玩家頭／槍口／方向、健康／彈匣／備彈／換彈／參戰、頭旋轉／左右手位置旋轉與來源、敵軍位置／健康、環境與 AI 政策，以及自前幀以來完整世界事件。最多 25 玩家、100 敵軍、500 事件／幀；向量／四元數／房間界線及事件格式有界。24 小時／100 萬幀為目前硬限制，不代表已測此容量。

觀察序號須為已接受管理歷史。政策／名冊與該稀疏管理快照核對；管理中斷允許 `suspended=true` 的 Paused 記錄引用 Running，但不能假造新管理命令。四種統計事件必須逐筆對上已持久化的 combat report ID、stream sequence、origin、kind、player、shot、enemy 及 damage，且不引用比此幀更新的觀察。血量及剩餘彈藥與此前綴一致。非統計世界事件的 ID 亦跨幀唯一。

`complete=true` 要求最後一幀為 Ended、finalSequence 精確一致、戰鬥來源已 sealed、throughCombatSequence 對上 acceptedSequence，並核對最終玩家統計。API End 釋放房間不會替來源製造末幀或世界 seal。

SSE 以 `header`、`frame`、`status`、`complete` 事件輸出單行 JSON。frame 有 packet 及此刻 statistics；status 約每秒回 metadata。replay complete 後串流結束；live 可以繼續顯示最後結果。背壓直接等候 socket／HTTP 寫入，不建立每位觀察者的無界快照佇列。

## 儲存與驗證邊界

管理包 0.31.146 讀取觀戰錄製清單時，先依場次權限取得可見場次，再按原建立時間順序，每批至多讀取 128 個場次識別。每批收集錄製資料後釋放 SQLite 存取鎖，再解析標頭。持續發布中的各批可反映讀取當下已接受的尾端。需要查核同一場次最新狀態時，可讀取該場次的 `/world`。

`SessionDataDirectory/worlds.db` 使用 WAL／synchronous FULL，schema 1。recordings 保存不可變 header 及 cursor，world_frames 以 session／sequence 為鍵並建 elapsed 索引，world_event_ids 保證跨幀事件唯一。每幀、統計、事件 ID、cursor 在同一交易；拒絕／寫入失敗不留下部分幀。重啟不把整場幀載入記憶體，播放讀取當前幀。管理／戰鬥核心仍保留既有事件記憶體投影，未宣稱全系統恆定記憶體。

v0.14.1 另以可新增的 camera_bookmarks 表保存不可變位置、完整身分命名空間與移除 tombstone，沿用此資料庫與單一寫入程序租約；不改 header／世界幀／統計／updatedAtUtc 或 schema 1。移除不實體刪掉原請求內容，保留原樣重試的判斷資料；未實作清理 tombstone 或跨任務鏡頭範本。API／主控台需一起更新；共享 Runtime、Unity NGO protocol 14 及場次 envelope 6 不變。

備份前先停 API，再備份整份 API data（missions、events.db、worlds.db、簽章 key），另保留來源 NDJSON／combat journal；不要只拷貝開啟中的單一 db 而漏掉 WAL。沒有自動刪檔、壓縮、保留政策、備援及加密儲存。

檢查包含核心拒絕／交易回滾、真實發布／觀察、跨程序來源重送、API 重啟、房間範圍、來源中斷、瀏覽器鏡頭／回放／行動版面。`python scripts/smoke_world.py` 是額外必要檢查；瀏覽器仍用 `tests/browser/check.cjs`，隔離建置另設 `VR_COMMAND_WORLD_RELAY_DLL`。

GameServer 是受信任的權威來源；格式及統計一致不等於每條射線重新跑物理驗證，也不證明姿態來自真人頭盔。鏡頭位置保存已有 Simulation／HTTP／SQLite／瀏覽器驗證；尚待 Unity 真正編譯運行發布器、Quest 頭手採樣與實機重連、正式美術／動畫／聲音、MR 校正、長任務壓測及 25 台設備效能驗收。
