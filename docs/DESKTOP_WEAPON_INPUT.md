# 桌面玩家武器輸入

Windows 遊戲 0.50.5 在送出射擊或換彈前，會確認任務正在執行、管理連線就緒、玩家尚未結束任務，且伺服器已確認姿態、玩家身體仍連線及血量大於零。桌面與追蹤頭盔共用這些條件；追蹤頭盔另保留有效追蹤姿態與放開按鍵後才重新允許觸發的原有檢查。伺服器沿用原武器判定。

桌面控制為 Space 或滑鼠左鍵射擊、R 換彈。玩家被淘汰後，這些按鍵不再送出武器請求。移動、視角、武器傷害、彈藥、RPC 格式與任務時鐘沿用既有行為。

2026-11-11 以同一檢查工具，在兩個各自新建的同機 Windows 原生場次操作四次實際按鍵。每場先射擊一次、換彈一次，再讓原敵軍攻擊至血量歸零，最後再按 Space 及 R。下表為實際 HUD 重繪時取得的累計請求數。

| 觀察點 | 修正前診斷版本 | 0.50.5 |
| --- | ---: | ---: |
| 開始 | 0 | 0 |
| 存活射擊 | 1 | 1 |
| 存活換彈 | 2 | 2 |
| 淘汰 | 2 | 2 |
| 淘汰後按 Space | 3 | 2 |
| 淘汰後按 R | 4 | 2 |

兩場均記錄四次本機按鍵邊緣。淘汰後的管理就緒、姿態確認、身體連線與追蹤旗標均持續有效，實際血量為零。原伺服器各接受一發射擊及五次敵軍命中，最終耗損 100、健康 0；原玩家戰績、伺服器確認、CSV、雙封存及完整回放均相符。修正前 941 格、修正後 812 格，兩場 C／F 各 16 個執行資料檔雜湊一致。修正前因額外兩筆請求而以退出碼 1 保存，修正後退出碼 0。[核對紀錄](../artifacts/weapon-gate-native-validation.json)

檢查工具 `scripts/check-desktop-weapon-gate.py` 使用明確啟用的 `--vr-hud-trace`，在既有診斷中記錄本機按鍵數及武器提交序號。這些欄位不加入網路封包。工具每個階段列印檔案位置，操作者必須先在實際遊戲視窗完成指定按鍵，才可建立對應的 `alive-fire.done`、`alive-reload.done`、`eliminated-fire.done`、`eliminated-reload.done`。標記只推進觀察；仍須由原生按鍵計數、伺服器畫格與戰績通過斷言。全部操作須在原 HUD 診斷 285 秒期限內完成。

```powershell
python scripts/check-desktop-weapon-gate.py --api-dll <API-DLL> `
  --player-exe <Windows-Player-EXE> --runtime-root <新測試資料根目錄>
```

本次實際按鍵驗證限單機一名 Windows 玩家、原生遊戲伺服器及 Simulation 來源。實體頭盔、MR 場地、跨機及 25 位真人操作仍依場館驗收流程辦理。既有 OpenXR 啟動診斷與舊姿態失效根因持續追蹤。
